## Verification

Run before reporting any task as complete, and quote the last lines of the output:

```sh
uv run ruff check . && uv run ruff format --check . && uv run pytest -q && python3 scripts/commit_hygiene.py
```

Do not weaken a test or a check to make it pass; report the conflict instead.

## Working rules

- **Language.** Code, comments, documents and commit messages are in English.
- **Bounded tasks.** A brief names the goal, the files it may write (`owned_paths`), what is out of scope, and the commands that prove it is done. Work that grows beyond that stops and reports.
- **Explicit write scope.** Write only inside the brief's owned paths. `pyproject.toml` and `uv.lock` change only in a brief that owns them; a missing dependency is a reason to stop and report, not to add one.
- **Never invent data.** When a network call fails, a figure does not reconcile or a source field is missing, stop and report. No placeholder or estimated numbers in `data/`, `docs/golden/` or a test expectation that claims to come from the source.
- **Verification before completion.** A claim that work was done is not evidence. Run the verification above and quote it.
- **Concise reports, plain language.** Lead with the outcome and the verification result, then what changed and what remains. Short sentences, everyday words. No em dash or en dash as punctuation.
- **Commit history.** Commits carry the maintainer's identity. No attribution trailers (`Co-Authored-By`, `Signed-off-by`, `Claude-Session`) and no "generated with" or "generated by" lines; `scripts/commit_hygiene.py` and a CI step check the history. Subject shape `type(scope): subject`.
- **One brief, one branch, one pull request.** Never commit to `main`, never push `main`, never force-push, never merge. The maintainer merges, by rebase or by a squash whose message is clean.
- **Private notes stay local.** `HANDOFF.md`, `notes/` and `urls.txt` are gitignored working notes; never add them.

## Unattended sessions (cloud)

- Your prompt names one brief. Read this file, the brief and every file the brief points to before writing.
- The environment holds no secrets and the work needs none. Never ask for, write or print a key.
- Network: package installs and the USAspending hosts (`api.usaspending.gov`, `files.usaspending.gov`) only.
- Work on a branch named after the brief's `task_id`, created from `main`. Commit in small steps and push the branch (`git push -u origin <task_id>`) after each sound step, so nothing is lost if the session stops.
- Never wait for input. When blocked (network refused, unclear rule, a check you cannot satisfy), commit what is sound, write the `Blocked` section of your report, push the branch, and stop.
- Work in depth. There is no token or time budget to save. Plan first; use subagents for reading, for independent parts and for second opinions. When the done list is met, deepen inside the owned paths (edge cases, failure tests, clearer docs); never widen the scope.
- Before the final push, have a subagent that did not write the code review the whole diff against the brief's `done_means` and the Code Review Rules below, from the diff and the brief only. Fix each finding or list it in the report with the reason it stays.
- Close by committing your report as `tasks/reports/<task_id>.md` (outcome, verification output, the figures the brief asks for, open questions) and pushing the branch. The owner opens the pull request from the pushed branch. Never push `main`, never merge.

## Code Review Rules

Every review of a diff, by a person or a tool, reads it through a security lens as well as for correctness. It reports each finding by file and line, with the rule it breaks and a short reason, and never quotes a secret value.

- **Injection.** Input from a user, a file, a model or the network never reaches a shell, a query, a template or `eval` unescaped. Build commands as argument lists, not strings. SQL values are bound parameters (ADR-0002 point 4).
- **Secrets.** No key, token, password or private key in code, tests, fixtures, logs or messages. Test strings that look like secrets are built by concatenation.
- **Subprocess and paths.** No `shell=True` on outside input. A path from input is resolved and checked to stay inside its root; no `..` escape, no symlink jump.
- **Permission widening.** A change that widens a permission, an allow list, a hook matcher, a token scope or a CI permission says why in the pull request.
- **Dependency changes.** A new or upgraded dependency, action or tool names its version and source, and is pinned.

A finding blocks the merge until it is fixed or the maintainer rules on it in writing.

## Enforcement

Mechanically enforced in CI (`.github/workflows/ci.yml`): ruff, the test suite, the commit-history check, and that every commit of a pull request is authored by the maintainer. Enforced by `.claude/settings.json`: no attribution in commits or pull requests, no push to `main`, no force-push, no remote changes. Documented guidance only: bounded tasks, write scope, report style, the Code Review Rules.
